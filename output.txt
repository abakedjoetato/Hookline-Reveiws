4. AUTHENTICATION
========================================================================

**Features Implemented:**
- **Registration**: Allows users to register. Argon2id hashes the password, and an email verification token is dispatched via Nodemailer.
- **Login**: Compares the email and hashed password, checks `AccountStatus`, handles the failsafe rate limit, and establishes an opaque `HttpOnly` Secure session cookie.
- **Logout**: Specifically revokes the session matching the current request cookie identifier.
- **Logout All**: Revokes *all* active sessions for a user, forcing re-authentication everywhere.
- **Session rotation**: Successfully rotates sessions upon sensitive state changes (like Password Reset or Role Escalation).
- **Password reset**: Emits a single-use hashed token to the email on file. Applying the token rotates the password (hashing it again with Argon2id) and revokes all active sessions.
- **Email verification**: Takes the token dispatched during registration and marks the user as verified.
- **Reauthentication**: Used prior to performing sensitive admin tasks; verifies the password again and rotates the session securely.
- **Session listing**: Lists all actively unexpired and unrevoked sessions mapped to the current user ID.
- **Session revocation**: Revokes an explicit, individual session ID for a user.
- **Admin invitation acceptance**: Validates hashed tokens specifically issued by an OWNER_ADMIN to promote a new or existing user to MODERATOR/OWNER_ADMIN.

**Final Session Architecture:**
The architecture relies entirely on opaque, cryptographically secure random session tokens (32 bytes generated via standard cryptography suites) combined with server-side validation against PostgreSQL. The raw tokens are NEVER persisted; only a SHA-256 hash is stored in `UserSession`. The raw token is delivered exactly once to the client as an `HttpOnly`, `Secure`, `SameSite=Lax` cookie. There are no client-decodable JWTs. Expiration is controlled natively via DB validation of `idleExpiresAt` and `absoluteExpiresAt`.

========================================================================
5. AUTHORIZATION
========================================================================

**Role Resolution**: `SessionService` intercepts requests on protected routes, parses the cookie, and joins `UserRoleAssignment` against the user. Roles are securely cached on the request execution context.
**Permission Resolution**: Similarly retrieves `UserPermissionAssignment` arrays to evaluate granular capabilities (e.g. `PAYMENT_RECORD_VIEW`).
**Override Precedence**: Explicit DENIAL overrides supersede global Grants. Direct Grants supersede Role omissions.
**Owner Administrator Safeguards**: Deletion or demotion of the final OWNER_ADMIN is strictly blocked in `AdminInvitationService` and Database domains via transactional row-locking counts.
**Moderator Restrictions**: Moderators are explicitly prevented from executing endpoints mapped to `ADMIN_MODERATOR_MANAGE`, `ADMIN_ROLE_MANAGE`, or any Stripe configuration directives.
